Does MSK run within a VPC or outside VPC?

---


**Amazon MSK (Managed Streaming for Apache Kafka) runs WITHIN a VPC.**

Key points:

- **VPC-native service**: MSK clusters are deployed inside your VPC across multiple Availability Zones
- **Private by default**: Brokers get private IP addresses from your VPC subnets
- **Network isolation**: You control access via security groups and network ACLs
- **Connectivity options**:
  - **Within VPC**: Direct access from EC2, Lambda (with VPC config), ECS, etc.
  - **Cross-VPC**: VPC peering or AWS Transit Gateway
  - **On-premises**: AWS Direct Connect or VPN
  - **Internet**: Requires public access configuration (not recommended for production)

**Architecture implications**:
```
Your VPC
├── Subnet AZ-1 (Private)
│   └── MSK Broker 1
├── Subnet AZ-2 (Private)
│   └── MSK Broker 2
├── Subnet AZ-3 (Private)
│   └── MSK Broker 3
└── Security Groups
    └── Control inbound/outbound traffic
```

**For your Restaurant Booking System**: If you add MSK for event streaming (bookings, payments), you'd deploy it in private subnets with security groups allowing access only from your Lambda functions or application servers.

I am provide with a MSK broker endpoint, a MSK topic name and an IAM Role. How I can connect it from a different VPC?

---


To connect to MSK from a different VPC, you need **network connectivity** + **IAM authentication**. Here are the options:

## Option 1: VPC Peering (Recommended for same region)

**Setup:**
```bash
# 1. Create VPC peering connection
aws ec2 create-vpc-peering-connection \
  --vpc-id vpc-YOUR_VPC \
  --peer-vpc-id vpc-MSK_VPC \
  --peer-region us-east-1

# 2. Accept peering (if different accounts, accept from MSK account)
aws ec2 accept-vpc-peering-connection --vpc-peering-connection-id pcx-xxxxx

# 3. Update route tables in YOUR VPC
aws ec2 create-route \
  --route-table-id rtb-YOUR_RT \
  --destination-cidr-block 10.0.0.0/16 \
  --vpc-peering-connection-id pcx-xxxxx

# 4. Update route tables in MSK VPC
aws ec2 create-route \
  --route-table-id rtb-MSK_RT \
  --destination-cidr-block 172.31.0.0/16 \
  --vpc-peering-connection-id pcx-xxxxx

# 5. Update MSK security group to allow inbound from your VPC CIDR
aws ec2 authorize-security-group-ingress \
  --group-id sg-MSK_SG \
  --protocol tcp \
  --port 9098 \
  --cidr 172.31.0.0/16
```

## Option 2: AWS Transit Gateway (Multi-VPC/Multi-region)

**Setup:**
```bash
# 1. Create Transit Gateway (if not exists)
TGW_ID=$(aws ec2 create-transit-gateway --query 'TransitGateway.TransitGatewayId' --output text)

# 2. Attach both VPCs
aws ec2 create-transit-gateway-vpc-attachment \
  --transit-gateway-id $TGW_ID \
  --vpc-id vpc-YOUR_VPC \
  --subnet-ids subnet-xxx subnet-yyy

aws ec2 create-transit-gateway-vpc-attachment \
  --transit-gateway-id $TGW_ID \
  --vpc-id vpc-MSK_VPC \
  --subnet-ids subnet-aaa subnet-bbb

# 3. Update route tables to route through TGW
```

## Python Client Code (IAM Authentication)

```python
# src/tools/msk_producer.py
import boto3
from kafka import KafkaProducer
from aws_msk_iam_sasl_signer import MSKAuthTokenProvider

class MSKProducer:
    def __init__(self, bootstrap_servers: str, topic: str, region: str = "us-east-1"):
        self.topic = topic
        self.region = region
        
        # IAM authentication token provider
        def token_provider():
            token, _ = MSKAuthTokenProvider.generate_auth_token(region)
            return token
        
        # Kafka producer with IAM auth
        self.producer = KafkaProducer(
            bootstrap_servers=bootstrap_servers,
            security_protocol='SASL_SSL',
            sasl_mechanism='OAUTHBEARER',
            sasl_oauth_token_provider=token_provider,
            client_id='restaurant-booking-producer'
        )
    
    def send_booking_event(self, booking_data: dict, correlation_id: str):
        """Send booking event to MSK topic"""
        message = {
            "correlation_id": correlation_id,
            "event_type": "booking_created",
            "data": booking_data
        }
        
        self.producer.send(
            self.topic,
            key=correlation_id.encode('utf-8'),
            value=str(message).encode('utf-8')
        )
        self.producer.flush()
```

## Lambda Function Example (VPC-enabled)

```python
# src/tools/msk_booking_publisher.py
import json
from kafka import KafkaProducer
from aws_msk_iam_sasl_signer import MSKAuthTokenProvider

# Environment variables
MSK_BOOTSTRAP = "b-1.msk-cluster.xxxxx.kafka.us-east-1.amazonaws.com:9098"
MSK_TOPIC = "restaurant-bookings"

def lambda_handler(event, context):
    """Lambda to publish booking events to MSK"""
    
    def token_provider():
        token, _ = MSKAuthTokenProvider.generate_auth_token("us-east-1")
        return token
    
    producer = KafkaProducer(
        bootstrap_servers=MSK_BOOTSTRAP,
        security_protocol='SASL_SSL',
        sasl_mechanism='OAUTHBEARER',
        sasl_oauth_token_provider=token_provider
    )
    
    booking_data = json.loads(event['body'])
    
    producer.send(
        MSK_TOPIC,
        key=booking_data['booking_id'].encode('utf-8'),
        value=json.dumps(booking_data).encode('utf-8')
    )
    producer.flush()
    
    return {"statusCode": 200, "body": "Event published"}
```

## Key Points

1. **Network**: VPC Peering or Transit Gateway for connectivity
2. **Security Group**: MSK SG must allow port 9098 from your VPC CIDR
3. **IAM Auth**: Use `SASL_SSL` + `OAUTHBEARER` with MSK IAM token provider
4. **Lambda**: Must be VPC-enabled with route to MSK VPC
5. **Port**: 9098 for IAM auth (not 9092)

**Quick test:**
```bash

telnet b-1.msk-cluster.xxxxx.kafka.us-east-1.amazonaws.com 9098
```

Follow up to the same question: I am having a Lambda running within in a VPC to access Aurora Database. Will I be able to connect the Kafka Topic as a trigger for my Lambda funtion?

---


**Yes, you can use MSK as a Lambda trigger, BUT there are critical networking requirements:**

## Key Requirements

1. **Same VPC or Connected VPCs**: Lambda must have network access to MSK brokers
2. **VPC Configuration**: Your Lambda is already VPC-enabled (for Aurora), which is good
3. **Cross-VPC**: If MSK is in a different VPC, you need VPC Peering or Transit Gateway

## Setup MSK Event Source Mapping

```bash
# Create MSK trigger for Lambda
aws lambda create-event-source-mapping \
  --function-name process-booking-events \
  --topics restaurant-bookings \
  --source-access-configuration Type=VPC_SUBNET,URI=subnet-xxxxx Type=VPC_SUBNET,URI=subnet-yyyyy Type=VPC_SECURITY_GROUP,URI=sg-zzzzz \
  --self-managed-kafka-event-source-config '{"ConsumerGroupId":"lambda-consumer-group"}' \
  --starting-position LATEST \
  --batch-size 100 \
  --maximum-batching-window-in-seconds 10
```

## Lambda Function Code

```python
# src/lambda/process_booking_events.py
import json
import base64
import pymysql
from typing import List, Dict

# Aurora connection (existing)
def get_db_connection():
    return pymysql.connect(
        host=os.environ['AURORA_ENDPOINT'],
        user=os.environ['DB_USER'],
        password=os.environ['DB_PASSWORD'],
        database='restaurant_booking'
    )

def lambda_handler(event, context):
    """
    Process Kafka messages from MSK and write to Aurora
    
    Event structure from MSK:
    {
        "eventSource": "aws:kafka",
        "eventSourceArn": "arn:aws:kafka:...",
        "records": {
            "restaurant-bookings-0": [
                {
                    "topic": "restaurant-bookings",
                    "partition": 0,
                    "offset": 123,
                    "timestamp": 1234567890,
                    "key": "booking_123",
                    "value": "base64_encoded_message"
                }
            ]
        }
    }
    """
    
    conn = get_db_connection()
    cursor = conn.cursor()
    
    processed = 0
    failed = 0
    
    try:
        # Process all partitions
        for partition, messages in event['records'].items():
            for record in messages:
                try:
                    # Decode Kafka message
                    message_bytes = base64.b64decode(record['value'])
                    message = json.loads(message_bytes.decode('utf-8'))
                    
                    # Extract booking data
                    booking_id = message['data']['booking_id']
                    user_id = message['data']['user_id']
                    restaurant_id = message['data']['restaurant_id']
                    
                    # Write to Aurora
                    cursor.execute("""
                        INSERT INTO bookings (booking_id, user_id, restaurant_id, status, created_at)
                        VALUES (%s, %s, %s, 'confirmed', NOW())
                        ON DUPLICATE KEY UPDATE status='confirmed'
                    """, (booking_id, user_id, restaurant_id))
                    
                    processed += 1
                    
                except Exception as e:
                    print(f"Failed to process record: {e}")
                    failed += 1
        
        conn.commit()
        
        return {
            'statusCode': 200,
            'body': json.dumps({
                'processed': processed,
                'failed': failed
            })
        }
        
    finally:
        cursor.close()
        conn.close()
```

## Network Configuration (Critical)

### Scenario 1: MSK and Lambda in SAME VPC
```bash
# Lambda already has VPC config for Aurora
# Just add MSK security group to Lambda's security groups
aws lambda update-function-configuration \
  --function-name process-booking-events \
  --vpc-config SubnetIds=subnet-xxx,subnet-yyy,SecurityGroupIds=sg-lambda,sg-msk-access
```

### Scenario 2: MSK in DIFFERENT VPC (Your Case)

**Step 1: Create VPC Peering**
```bash
# Create peering between Lambda VPC and MSK VPC
aws ec2 create-vpc-peering-connection \
  --vpc-id vpc-LAMBDA_VPC \
  --peer-vpc-id vpc-MSK_VPC

# Accept peering
aws ec2 accept-vpc-peering-connection --vpc-peering-connection-id pcx-xxxxx
```

**Step 2: Update Route Tables**
```bash
# Lambda VPC route to MSK VPC
aws ec2 create-route \
  --route-table-id rtb-LAMBDA_RT \
  --destination-cidr-block 10.0.0.0/16 \
  --vpc-peering-connection-id pcx-xxxxx

# MSK VPC route to Lambda VPC
aws ec2 create-route \
  --route-table-id rtb-MSK_RT \
  --destination-cidr-block 172.31.0.0/16 \
  --vpc-peering-connection-id pcx-xxxxx
```

**Step 3: Update MSK Security Group**
```bash
# Allow Lambda security group to access MSK on port 9098
aws ec2 authorize-security-group-ingress \
  --group-id sg-MSK \
  --protocol tcp \
  --port 9098 \
  --source-group sg-LAMBDA
```

## Terraform/CloudFormation Example

```python
# deploy_msk_lambda_trigger.py
import boto3

lambda_client = boto3.client('lambda')

# Create event source mapping
response = lambda_client.create_event_source_mapping(
    FunctionName='process-booking-events',
    EventSourceArn='arn:aws:kafka:us-east-1:ACCOUNT:cluster/CLUSTER_NAME/UUID',
    Topics=['restaurant-bookings'],
    StartingPosition='LATEST',
    BatchSize=100,
    MaximumBatchingWindowInSeconds=10,
    SelfManagedKafkaEventSourceConfig={
        'ConsumerGroupId': 'lambda-booking-processor'

    SourceAccessConfigurations=[
        {'Type': 'VPC_SUBNET', 'URI': 'subnet-xxxxx'},
        {'Type': 'VPC_SUBNET', 'URI': 'subnet-yyyyy'},
        {'Type': 'VPC_SECURITY_GROUP', 'URI': 'sg-zzzzz'},

print(f"Event source mapping created: {response['UUID']}")
```

## Key Points

✅ **Works**: Lambda can consume from MSK in different VPC with proper networking  
✅ **Existing VPC Config**: Your Lambda already has VPC config for Aurora  
✅ **Add MSK Access**: Just need VPC peering + security group rules  
⚠️ **Cold Start**: VPC Lambda has higher cold start latency  
⚠️ **Scaling**: Lambda scales based on partition count (1 Lambda per partition)  

**Architecture:**
```
MSK VPC (10.0.0.0/16)          Lambda VPC (172.31.0.0/16)
├── MSK Broker (port 9098) <──┐
└── Security Group             │ VPC Peering
                               │
                               └──> Lambda Function
                                    └──> Aurora Database
```
